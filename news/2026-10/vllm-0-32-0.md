# vLLM 0.32.0

**Rank:** 4  
**Release date:** 2026-10-18  
**Area:** Inference & Infrastructure  
**Primary source:** vLLM release notes  
**Availability:** Open-source release; installable from PyPI or buildable from source. 

## What Changed

NVFP4 KV-cache support extends to NVIDIA SM8x, SM90 and SM12x, with additional architecture-specific attention paths. ROCm gains `ultraquant_4bit`, which stores KV data in FP4 with per-group scales and Hadamard-rotated keys. Its optimized decode kernel applies to specific head dimensions and grouped-query configurations, with a Triton fallback. 

Model Runner V2 gains a GPU n-gram speculator that scans GPU-resident request token histories to propose drafts. New plumbing allows different requests to carry different numbers of valid draft tokens. 

## Why It Matters

Serving teams can test whether lower KV-cache memory use enables longer contexts or more concurrent requests, and whether GPU-resident speculation improves decode latency on repetitive workloads. Both should be evaluated against workload-specific throughput, latency and output quality; hardware and attention-backend compatibility matter.

## Evidence

**Kind:** Public release and implementation  
**Independently validated:** no

The vLLM release notes and merged implementation pull requests document the changes. The UltraQuant developers report approximately twice the KV density of FP8; that is a **developer-reported** figure, not an independent measurement. The checked sources do not independently reproduce the new KV-cache and Model Runner V2 speculation paths. 

## Assessment

- **Technical novelty:** meaningful — existing quantized caching and n-gram speculation gain broader hardware coverage and GPU-resident, variable-length draft handling.
- **Practical significance:** high — serving teams constrained by KV memory or decode latency should benchmark the relevant paths on their own models and hardware.
- **Confidence:** medium — the release and implementation were checked, but performance and quality for these paths remain developer-reported or unverified.

## GitHub signal

**Ideas worth investigating:**

- Keep request token histories densely GPU-resident for repeated n-gram scans.
- Propagate per-request valid draft lengths through speculative decoding.
- Combine FP4 KV storage, group scales and Hadamard-rotated keys with an optimized decode kernel.
